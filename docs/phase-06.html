01Why this jumped the queue

Phase 06 was built before phase 03, out of roadmap order.

At the end of phase 02 the editor could build a scene, manipulate it directly and undo its way out of mistakes — and lose all of it the moment the window closed. Textures were next on the roadmap, but building them first would have meant two things: a tool that still could not be used on a real page, and every texture test starting from an empty scene.

The argument

Grey boxes are already useful. What a background blockout has to give you is correct perspective to draw over, not a textured render. So save plus load made the tool earn its keep in the state it was already in, and made the next phase cheaper to build at the same time.

02The Rust side

Two commands in src-tauri/src/lib.rs, and a plugin for the pickers.

File dialogs come from tauri-plugin-dialog. The reading and writing does not use tauri-plugin-fs — it is two hand-written commands instead.

Why not the fs plugin

That plugin gates access with a path scope declared at build time, which fights a file picker whose paths only exist at runtime. Two narrow commands sidestep the whole problem, and neither can enumerate a directory — so there is nothing to walk outward from a path the user chose. It also puts the Rust where the Rust was wanted.

The write is atomic

A save goes to a temp file beside the target, is flushed to the device with sync_all(), and is then renamed over the target. Rename is atomic on every platform this ships to.

Why it matters here specifically

The project lives in a OneDrive folder. Overwriting in place means a crash, a full disk or a sync hiccup midway through leaves a half-written file where a working scene used to be. With the rename, a failed save leaves the previous version intact — which is the exact failure this phase exists to prevent.

A read ceiling

A scene is plain JSON describing primitives, so even a busy one lands well under a megabyte. Reads are capped at 64 MB so that pointing Open at the wrong file fails with a message instead of trying to allocate it.

// the whole Rust surface
#[tauri::command] read_text_file(path)            // metadata check, size cap
#[tauri::command] write_text_file(path, contents) // temp → sync → rename

03The file format

.playstage — the SceneFile shape from types/scene.ts, as JSON.

Nothing new had to be designed. SceneFile, toSceneFile() and loadScene() were already in place from phase 01, because the data model was built around the on-disk format from the start. This phase only had to move bytes.

The output is indented, not minified. These files are small, they are the user's own data, and being able to open one in a text editor or diff two of them is worth more than the bytes saved.

FieldHolds
formatThe literal "playstage-scene" — the marker a loader checks first.
versionInteger. A file from a newer version is refused rather than guessed at.
nameDisplay name. Reset from the filename on save-as and open.
objectsFlat array; hierarchy lives in parentId.
hotspotsSaved camera angles. Filled in by phase 05.
texturesDeclared, unused until phase 03.

04Repair, don't refuse

src/io/sceneFile.ts. The largest single piece of this phase, and the least obvious.

Everything that comes back off disk is untrusted input, even when Playstage wrote it. A file can be hand-edited, truncated by a crash mid-write, synced badly, or produced by a newer build. And the renderer is not tolerant of malformed input — two shapes of bad data could take the whole app down.

The two real crashes this closes

buildGeometry throws on extrude, lathe and csg specs, and SceneObjectView calls it inside a useMemo with no error boundary. One such object in a file took down the entire React tree. They now load as empty groups, keeping their transform, their place in the hierarchy and all of their children.

A cycle in parentId made SceneObjectView recurse until the stack overflowed. worldMatrix guarded against cycles; rendering never did. Cycles are now cut with a three-colour depth-first walk, iteratively, so making a deep file safe cannot itself overflow.

The posture

Fix what can be fixed, report every fix, refuse only what is genuinely meaningless. This is a drawing tool; throwing away an afternoon's blockout because one object had a bad rotation value would be indefensible.

Only three things are fatal: the text is not JSON, it is not a Playstage scene, or it comes from a future format version whose meaning cannot be guessed. Everything else is repaired and the repairs are listed in a dialog on open.

  • fixMissing primitive params filled from the spec — undefined reaches Three.js as NaN vertex data
  • fixOut-of-range params clamped; unknown keys dropped
  • fixZero scale nudged off zero, sign kept — a singular matrix makes any reparented child NaN
  • fixOrphans whose parent is missing moved to the top level, where they will actually draw
  • fixDuplicate ids reissued; children stay attached to the first occurrence
  • fixMaterial slots rebuilt from the primitive's own face count, so no holes or strays
  • fixUnparseable colours replaced — THREE.Color warns and silently keeps its old value
  • fixDangling texture ids cleared back to flat colour

Tested as hostile input

scripts/verify-scenefile.mjs runs 34 cases against the real parser, mostly malformed files. Each one corresponds to a way the app used to be breakable.

05New / Open / Save

src/io/documentActions.ts — plain async functions, not store actions.

They coordinate three stores and the filesystem, which is more than any one store should know about. Keeping them outside also makes them callable from a toolbar button, a keyboard shortcut and later a window-close handler without duplicating the sequencing. Each resolves to a boolean, so a caller chaining operations — "save before closing" — can tell cancellation from failure.

DetailReasoning
Non-reentrantA busy flag makes save and open mutually exclusive. Leaning on Ctrl+S during a slow write to a synced folder would otherwise start overlapping writes to one path.
Picker outside the guardThe dialog blocks on the user; holding the flag through it would wedge every shortcut behind it.
Dirty flag cleared lastOnly after the write resolves. Clearing it optimistically would show a saved scene that is not on disk.
Filename winsOn open, the scene is named from the file rather than the name inside it — that is what shows in Explorer, and the two can diverge after a rename.
Shortcuts beat fieldsCtrl+S fires even with a text field focused. Silently doing nothing there is how people lose work.

06Still outstanding

This phase is not finished; the half that was blocking real use is.

  • —PNG export at arbitrary resolution. The canvas already runs preserveDrawingBuffer, so the read-back works; it needs a size control, a background choice and a binary write command.
  • —Batch export — every saved hotspot in one pass. Now that phase 05 exists, this turns one scene into a full set of panel references in a single click.
  • —Recent files list.
  • —Window title reflecting the scene name and dirty state.
  • —Close guard on the Tauri window. New and Open already ask before discarding unsaved work; closing the window does not.
  • —Texture packing, so a scene file is portable. Waits on phase 03.
Format note

The loader accepts any version at or below the current one, so adding optional fields with sensible defaults is a cheap migration. The first candidate is storing projection mode per hotspot, which would take the format to version 2.
